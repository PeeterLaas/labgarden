# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Labgarden is a browser-only concept demo for a local-first research assistant and knowledge graph. It is a static site: no build step, no dependencies, no backend. The eLabFTW, Carpentries Workbench and R/Shiny + MCP integrations described on the page are proposals and aren't implemented in this repo. Keep the page's copy honest about that: it explicitly says it runs no inference and makes no integration writes.

## Commands

```sh
python3 -m http.server 8000 --directory dist   # run locally at http://localhost:8000
node --check dist/app.js                        # syntax check (the only JS "lint")
python3 scripts/check_assets.py                 # verify every local <script src>/<link href> in index.html exists
```

There are no tests. CI (`.github/workflows/check.yml`) runs the two checks on every push and PR.

## Deployment

- Pushes to `main` run the same checks, then publish `dist/` to GitHub Pages at https://peeterlaas.github.io/labgarden/ (`.github/workflows/pages.yml`).
- `.openai/hosting.json` configures a separate Sites deployment that also serves `dist/`. Leave it in place.
- Anything outside `dist/` is never served.

## Code structure

All of the shipped code is in three minified-style files, and each is written as one or a few very long lines:

- `dist/index.html`: all markup for the three sections: `#workspace` (interactive demo), `#ideas` (three product directions) and `#roots` (architecture and ecosystem).
- `dist/app.js`: vanilla JS with no framework or modules. It uses the `$`/`$$` helpers for `querySelector`/`querySelectorAll`.
  - The demo state is the `inbox` and `reviews` arrays. They're seeded from `initialInbox` and `initialReviews` and restored by `reset()`. State lives only in memory, so a reload resets it.
  - `render()` rebuilds the inbox and review lists and the counters from that state. Mutate state, then call `render()`.
  - Interactive elements are wired by `data-*` attributes (`data-view`, `data-project`, `data-idea`, `data-node`) and by element IDs. Changing an ID or data attribute in `index.html` means changing `app.js` too. The review accept and dismiss buttons are generated by `render()` with `data-review`/`data-action`, and they're handled by one delegated click listener on `#reviewlist`.
  - The `#ideas` panel text comes from the `ideas` array in `app.js`, indexed by `data-idea`. Entry 0 is also hard-coded as the initial HTML, so keep the two in sync.
  - User-supplied text has to go through `esc()` before it's interpolated into `innerHTML`. Uploaded files are only listed by name and type; their contents are never read.
- `dist/style.css`: all of the styling.

Because the files are one long line each, edit with exact-string replacements rather than line-based tools. After any change, run both checks.
